1. The methodology in brief

The Landry Family Equity Investment Operating System targets long-term appreciation over a 3–10 year horizon with capital preservation (a <30% drawdown objective). It is a bottom-up, quality-at-reasonable-price process: fundamentals determine direction; technicals refine timing — never the reverse.

Scoring: three tiers, one composite

Every candidate is scored 1–5 on twelve indicators, each with a weight and a confidence tag (High / Medium / Low):

TierIndicators (weight)Share of decision
Tier 1 — core economicsFCF Yield & Trend (20%), Revenue Growth Consistency (15%), Competitive Moat (15%), Revenue Visibility (10%), FCF Margin Trend (10%)70%
Tier 2 — quality confirmationManagement & Capital Allocation (8%), Valuation Multiples (8%), ROIC vs WACC (6%), Relative Strength vs SPY (3%)25%
Tier 3 — timing refinementTechnical Trend (2%), Analyst Consensus (2%), Volume/Accumulation (1%)5%

Composite Score = (Σ score × weight) × 20, giving 0–100. Decision bands: 80–100 STRONG BUY 65–79 BUY 50–64 WATCH LIST 35–49 AVOID <35 PASS

Four hard rules gate the score itself: a Tier 1 weighted average below 3.0 can never be a Buy (Rule 1 — score Tier 1 first; if it fails, stop); any Tier 1 indicator at 1 forces a qualitative review (Rule 2); two or more Tier 1 indicators at ≤2 auto-classifies Avoid (Rule 3); two or more Low-Confidence Tier 1 scores cap Strong Buy at Buy (Rule 4).

Entry, sizing, exit

A qualifying score does not authorize a purchase. The Entry Checklist (Rules 5–13) also requires: technical staging (above or recently reclaimed the 200-week MA → full initial size, otherwise 50% + a 90-day review; a negative monthly MACD holds you at 50% but never vetoes a qualifying fundamental case), no unhandled binary-event risk, an implied 5-year return >10% in the Base Case and ≥0% in a documented Bear Case, Bull/Base/Bear scenarios with exactly one tagged Likely, and a valuation ceiling (no new position above 50× P/FCF without documented >30% FCF growth and a passing bear case).

Position sizing (Rules 14–20) converts conviction to exposure: Strong Buy 5% initial / 8% max; Buy 3% / 5%; modifiers of ±1% for insider buying, Debt/FCF > 4×, customer concentration, macro headwinds; a beta overlay (−1% at β 1.40–1.59, −2% at ≥1.60); hard caps of 8% per position, 25% per sector, 12-position minimum, and 5–15% cash. Never lower the score threshold to get invested — hold cash instead.

Sell discipline (Rules 21–35) separates deterioration from volatility. Fundamental triggers (FCF collapse, moat loss, ROIC<WACC two years, destructive management, sustained revenue decline) act within 30 days. Valuation triggers (Debt/FCF>6×, P/FCF>50× with slowing growth, implied return <7%, oversized positions) force trims. Score downgrades follow a state machine: 50–64 = Probationary Hold (no additions, 90-day re-score); 35–49 = Exit Review (sell in 30 days unless a documented remediation plan exists); <35 = mandatory sell. Hold Through protects intact businesses from being sold on noise — a 20–30% price drop, one bad quarter, downgrades, or a market selloff are never, alone, reasons to sell.

Portfolio-level risk

A macro overlay (rate cycle, inverted yield curve, HY spreads > 600bp, SPY below its 200-week MA) adjusts sizing and urgency without touching business scores. The correlation cap (Rule 36) flags any cluster of 3+ holdings pairwise-correlated above 0.70: new additions to a flagged cluster start at 50% size, and cluster exposure above 20% needs written approval. The drawdown response (Rule 37) raises the cash floor and restricts new buying as portfolio drawdown deepens (see the tables below), entered after 5 consecutive days beyond a threshold and exited after 10 days back inside. Tax rules (38–42) govern how — never whether — a justified trade executes.

2. What is automated vs. what is yours

The Part 12 boundary is the design center of this tool. Automation applies only to raw market data and arithmetic. The judgment calls are never automated.

The app computesYou (or AI-drafts you approve) decide
Prices, market data, weekly returns, correlations and cluster flags, drawdown regime, beta, 200-week MA / MACD / Supertrend / A-D line, relative strength, FCF & Debt/FCF & revenue CAGR from statements, all composite math, every rule check, deadlinesCompetitive Moat, Management Quality, Revenue Visibility, structural-deterioration calls, scenario assumptions (Year-5 FCF, terminal multiples), binary-event judgment, remediation plans

AI (landry draft) may propose judgment scores with cited evidence, but a score counts for nothing until you approve it — every approval is recorded with name and timestamp in an audit trail. Quantitative drafts carry confidence ceilings (Medium for yfinance-grade data, Low for thin history) so data quality is visible in the score itself.

3. Setup

# one-time
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install anthropic          # optional — only for AI drafting

# start the dashboard
python webapp.py               # open http://127.0.0.1:8713

The web UI has two nav rows: the original backtester tabs, and the Landry row — L·Dashboard, L·Actions, L·Approvals, L·Risk. Everything the UI shows is also available from the CLI; both read and write the same files, so they stay interchangeable.

For AI drafting, set ANTHROPIC_API_KEY in your environment.

4. One-time: seed the score store from the workbook

  1. Your existing analyst scores live in the workbook's Scoring tab. Import them once: 
    python -m landry import --by "Taylor"
    This copies every recorded indicator score into landry_scores.json as approved-by-you (the workbook was the original approval), with a full audit entry per score.
  2. Verify the engine reproduces the workbook exactly: 
    python -m landry score --all        # engine vs workbook, flags any MISMATCH
python -m landry score NVDA --store # composite from the imported store
    Every one of the 16 scored names should match to the decimal (NVDA 93.2 STRONG BUY, etc.). The L·Dashboard tab shows the same cross-check continuously.

5. The daily routine (~2 minutes)

  1. Refresh data and get your action list (run after market close, or schedule it — cron: 30 13 * * 1-5 PT): 
    python -m landry daily --refresh
    or open L·Actions in the web UI. Items arrive in three groups, each with its rule citation and deadline:
    GroupExamples
    ACT NOWMandatory Sell / Exit Review deadlines (Rules 31/33), a held name that failed the Tier 1 gate, a >20% loss needing a post-mortem (Rule 46), a correlation cluster over the 20% cap (Rule 36)
    DUE SOONProbationary Hold 90-day re-scores (Rule 32), annual re-scores overdue (Rule 44), watch-list quarterly reviews (Rule 43), active macro-overlay conditions
    HOUSEKEEPINGStale data snapshot, drafts awaiting your approval
  2. Glance at L·Dashboard: the verdict strip shows holdings by decision band, equity vs cash %, data freshness, and open action counts. The score table color-codes bands and flags any engine-vs-workbook mismatch.
  3. Check L·Risk when anything changed: flagged correlation pairs and clusters (over-cap highlighted), macro conditions (unknowns are labeled unknown — the system never guesses), and each holding's beta, Rule 20 size cut, and Rule 8 staging status.

6. Scoring a new candidate (the full workflow)

  1. Pull the objective inputs: 
    python -m landry refresh --tickers ACME
    This computes technicals, relative strength, beta, and — where statement data allows — drafts the quantitative indicators (FCF Yield & Trend, Revenue Growth Consistency, FCF Margin Trend) directly from the Part 2 rubrics, each with a stated rationale and a confidence ceiling.
  2. Assemble evidence for the judgment indicators. Create a JSON file where each entry is tagged with its source tier (1 = audited filings … 5 = commentary — the Part 10 hierarchy): 
    [
 {"text": "10-K: 92% of FY25 revenue under multi-year contracts; net revenue retention 118%.",
  "source_tier": 1, "source": "FY25 10-K p.34", "date": "2026-02-15"},
 {"text": "Earnings call: price increase of 7% announced with no disclosed churn impact.",
  "source_tier": 2, "source": "Q2 call transcript", "date": "2026-07-30"},
 {"text": "Analyst note: share gains vs top competitor for 3rd consecutive year.",
  "source_tier": 4, "source": "Bernstein initiation", "date": "2026-06-01"}
]
  3. Request AI drafts (requires ANTHROPIC_API_KEY): 
    python -m landry draft ACME --evidence acme_evidence.json
    The model proposes 1–5 scores for Moat, Management, and Revenue Visibility only where the evidence supports them, citing which entries back each score. Moat drafts state which of the four cross-check tests (pricing power, relative margins, retention, share trend) are evidenced — a 4–5 needs at least two. Evidence from weak sources caps the confidence tag in code, whatever the model says.
  4. Review and approve — on L·Approvals (per-row approve/reject with optional overrides) or the CLI: 
    python -m landry pending ACME
python -m landry approve ACME competitive_moat --by "Taylor"          # accept
python -m landry approve ACME management_quality --by "Taylor" --score 3   # override
python -m landry reject ACME revenue_visibility --by "Taylor" --reason "evidence too thin"
    Overrides record both the original draft and your final call. Nothing you have not approved can ever reach a composite.
  5. Compute the verdict: 
    python -m landry score ACME --store
    Rules 1–4 apply automatically. If Tier 1 fails, the process stops there by design — do not score Tier 2/3.

7. Deciding an entry

  1. Confirm the composite is ≥65 with Tier 1 intact (Rules 5–7 — automatic from the scorecard).
  2. Check staging on L·Risk / the snapshot: above or recently-reclaimed 200-week MA → full initial size; otherwise (or with negative monthly MACD) 50% + a 90-day technical review (Rules 8–9).
  3. Document Bull / Base / Bear scenarios — Year-5 FCF per share, a terminal multiple no higher than min(current, 5-year median), cumulative distributions. The engine checks: Base > 10%, Bear ≥ 0%, exactly one scenario tagged Likely and it must be the Base (Rules 11–12). A negative bear case kills the entry regardless of score.
  4. Confirm no unhandled binary event (Rule 10) and the valuation ceiling (Rule 13; for financials, the Rule 49 sector ceilings).
  5. Size it: the sizing engine applies band limits, modifiers, the beta overlay, macro multipliers, cluster staging, and drawdown-regime gates, and reports every adjustment with its rule. In an Elevated regime only Strong Buys may initiate; in Severe/Critical, nothing does.
Record the thesis, key risks, and review triggers at entry (Part 9's investment file), and add the entry to the workbook's Performance Tracking tab — cohort benchmarking (12% objective for Strong Buys, 10% for Buys) needs the original decision date.

8. Monitoring holdings & selling

  1. Re-score quarterly on material news and annually in full (Rules 43–44 — the action list tracks both clocks).
  2. After each re-score the engine reports: fired fundamental triggers (act within 30 days), valuation triggers, and band transitions with computed deadlines. A Strong Buy→Buy downgrade only trims to the Buy maximum; it is not a sale.
  3. Respect Hold Through. If the only "problems" are price action, a single missed quarter, downgrades, or a market selloff — and no trigger fired — the system will refuse to recommend selling. A fired trigger always outranks Hold Through.
  4. Replacing a laggard with a better idea must pass the five-condition gate (Rule 34): a ≥15-point score gap across two consecutive quarterly re-scores, full vetting of the new name, no Hold Through protection, a genuine capital constraint, documentation before execution — and at most once per holding per 12 months (Rule 35).
  5. Execute tax-aware (Part 8): mandated sells go on schedule regardless of tax; discretionary trims may wait up to 30 days to reach long-term treatment; the lot selector picks the lowest after-tax combination (losses first, then long-term gains) — confirm specific lots with the broker.

python -m landry import --by NAMEOne-time workbook → score store migration
python -m landry export [--scores] [--no-prices]Fill a copy of the Excel workbook (formulas preserved)
python -m landry doctorCheck this machine is ready to edit the workbook safely (Python version, LibreOffice, required packages) — run this before any programmatic xlsx edit, on every machine, since it's checked per-environment, not once

This project runs across multiple machines by design. A workbook edit that passes every check available without a real spreadsheet engine — well-formed XML, a clean openpyxl round-trip — can still fail once Excel actually opens it. doctor confirms LibreOffice (soffice) is on PATH; if missing, install it (brew install --cask libreoffice on macOS, winget install TheDocumentFoundation.LibreOffice on Windows) before editing the workbook on that machine. Once installed, python -m landry.xlsx_recalc <path.xlsx> recalculates every formula and reports Excel errors — run it after any programmatic edit, before calling it done.

12. Excel round-trip

The workbook remains fully usable. landry export writes a dated copy — weekly closes into Price History (the workbook's Returns and Correlation tabs recalculate on open), market data, the drawdown log, and (with --scores) approved scores into the Scoring tab. Computed columns stay as formulas, so Excel remains its own check on the engine. landry import goes the other way. If you restructure workbook tabs, update the column maps in landry/xlsx_io.py (the workbook's Schema Reference tab is the contract).

13. Caveats & the dry run

Data quality. Fundamentals come from yfinance and are not filings-grade; the Part 10 FCF definition (SBC deducted, normalized) deserves filings-based inputs for names you are actually buying. Drafts from thin data are confidence-capped for exactly this reason. The financial-sector thresholds (Rules 48–49) are the doc's own "reasoned defaults, not backtested" — review before relying on them.
Before retiring manual scoring, run the one-month dry run: score in both the app and the workbook side by side, run landry daily each weekday, and investigate every MISMATCH flag on L·Dashboard. The engine is pinned to Workbook 25 (supersedes Workbook 11) by 305 tests, but the dry run is what validates the workflow, not just the math.

If this guide and the rulebook ever disagree, the rulebook governs. Interpretation choices made in code (PPO-form MACD, immediate regime reset at a new high-water mark, conservative 50% staging on unknown technicals, and others) are documented in the module docstrings.
