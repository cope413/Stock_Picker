- **Current Positions' own Price column (col F) cannot be refreshed live by this tooling — whenever Python/LibreOffice touches the file it shows the hardcoded fallback number inside its formula; since 2026-10-05 `landry weekly` (and `landry market`, or `landry market --positions-only`, which needs no network) sets that number to Market Data's price each run (`landry.market.sync_fallbacks`; Alan approved, Journal row 90), so F is at worst as old as the last weekly refresh.** Before that the fallbacks were numbers typed in weeks earlier, and the ten ETFs — which have no Monitor row for STOCKHISTORY to live in — showed them even inside Excel: on 10/5/26 the sheet overstated the portfolio by $11.5K (MLPI, VFLO, DVY, SCHD, AVUV each 5-7% stale). Only the number inside the formula is rewritten; the sync skips zero-share rows, cash sweeps, rows without a Market Data price and any formula of an unexpected shape (reporting them), and `tests/test_landry_market.py` pins the live formulas to the expected shape. The formula chain is Current Positions!F → `INDEX/MATCH` into Monitor & Recheck Triggers!H → a STOCKHISTORY array formula, and STOCKHISTORY is a Microsoft-cloud data type that only resolves inside real Excel with a live connection — `xlsx_recalc`'s LibreOffice pass cannot touch it, so col H (and therefore Current Positions' displayed price) just keeps showing whatever was last live-refreshed the last time Alan had the file open in actual Excel. **Market Data (refreshed every Saturday by `python -m landry weekly`, or on demand with `python -m landry market`; yfinance-backed, a snapshot rather than live — check how recent it is) is the reliable source for a current price** — use it directly (ticker → Market Data!C) rather than trusting Current Positions' Price/Market Value columns for anything computed outside Excel. Found 2026-09-29 doing a post-travel portfolio revaluation: NVDA showed $230.36 in Current Positions against a genuinely live $227.21 in Market Data, a stale/fresh mismatch that would have gone unnoticed without cross-checking. **Exception, 2026-10-05: a workbook Alan has just saved from real Excel carries live prices** (the Excel-saved review copy that became the live file had Current Positions!F and Monitor!H populated from STOCKHISTORY, e.g. NVDA 233.95, and a portfolio total ~$6K higher), stored as cached values with Excel's rich-value metadata; the first tool write (any openpyxl save + LibreOffice recalc) strips them and the stale fallback returns, so don't treat them as durable and never run `xlsx_recalc` on such a file just to "refresh" it. **Promoting an Excel-saved review copy to be the live workbook** (Alan: "check the review copy; if it checks out, make it the original"): compare formulas/constants cell by cell (it was 3 header labels, nothing else), list structure/format differences (Excel omits default attributes, writes alignment/page setup differently -- noise -- while freezes, hidden rows, widths, fonts, conditional formats are real), round-trip a scratch copy through openpyxl + `xlsx_recalc` and diff again to see what a tool write would lose, run `landry db status`/`audit`/the tests/`weekly --dry-run` against it, then `mv` it over `LANDRY_SYSTEM_WORKBOOK_25.xlsx` (keep the previous file in the scratchpad) and delete the review copies once Excel has them closed.

- **Price History is maintained ONLY by `python -m landry prices` (built 2026-10-04) — never by hand and never by `landry export`.** `status` is the read-only health check (duplicate/blank header tickers, holdings with no column, weeks behind). `append` adds the completed Friday(s) after the last row — it refuses an unfinished week, a >35% jump or a provider gap — extends Returns (Calc) ONE ROW AHEAD of the data (row n holds the return of Price History row n+1 over row n), moves the "NN Weeks" footer and the charts below the data, and recalcs. `rebuild` rewrites every close under the existing header from one dividend-adjusted pull; run it each quarter (it is QTR-REVIEW's Correlation Matrix step) because yfinance restates earlier closes for every dividend, so appended rows slowly drift from old ones. `add TICKER` gives a new holding a column (a free slot in B-V, else the next column from W), extends Returns (Calc) — columns AP+ for Price History W+, because Returns (Calc)'s W-AO hold the 19 charts' "trend" block — and the Correlation Matrix (rows/columns follow the Price History column; W-AF are its buffer). Cadence: after each Friday close; it will not write the current week early. Prices are dividend-adjusted weekly closes (`data_auto.weekly_closes`), so changes are total returns, as Rule 38 asks. **Why it exists:** around 2026-10-01 `landry export`'s Price History block (it wipes A3:Q162 and writes only the first 16 tickers alphabetically) silently destroyed the tab's layout — SPMO and V twice, VRT/VRTX/HELO gone, JEPQ/VFLO and the duplicate columns five weeks out of alignment (their correlations read ~0), eight held positions with no column, the 19 charts plotting the wrong tickers — and the 10/2 row held interim prices up to 9% off; found 10/4 when Alan asked how to record weekly closes efficiently. That block is retired (`export_workbook` refuses `weekly_closes`), the layout is restored and extended to all 26 holdings, and `landry audit` has a `price_history` check for each failure mode. The 19 charts and their trend columns are keyed to the ORIGINAL tickers' columns B-V; DVY, SCHD, VYM, MLPI, JEPI, GE and NFLX have none (Open Items #26). Returns (Calc)'s W-AO trend columns are live, not placeholders — an older note here said otherwise and was wrong. They are the SAME formula in every row, anchored to Price History row 3 (`append` copies them verbatim and translates only the row-relative return/date formulas — translating them slid the anchor in the first rehearsal), and they must find the last row from Returns (Calc) column A: finding it with `MATCH(9.99E+307, 'Price History'!A:A)` hit the footer's COUNT (the last number in that column) and sent every trend line to 0, and ADBE's to an error, until 10/4. Don't put a number in a column that a `MATCH(9.99E+307, …)` scans. Rehearse any change to this path on a scratch copy of the live workbook with simulated data before touching the real file — the synthetic unit-test fixture did not catch that.

- **The weekly Friday-close routine is `python -m landry weekly` (built 2026-10-04; scheduled task `landry-weekly-friday-close`, Saturdays ~8:00 local; Alan approved it 10/4 with "yes to both").** It runs `prices append` (above), then refreshes Market Data C:I and Monitor & Recheck Triggers col J (Next/Last Earnings Date) in place from yfinance (`landry/market.py`) -- plus Current Positions' fallback prices and, since 10/5, Performance Tracking's SPY benchmark cells -- then ONE recalc, then reads Rule 38's status back, runs the audit and the Journal / Drawdown Log drift guard (the report's `Database` line; a disagreement makes the run "need attention" -- resolve with `landry db pull` or `db regenerate`); `landry market` is the same minus Price History. Exit status: 0 clean, 1 Excel has the workbook open (nothing changed; any later run catches up every missed Friday), 2 ran with something needing attention. **It never commits: a modified workbook on a weekend (or Monday morning) is probably its output — check `git diff --stat`, `landry prices status` and the scheduled run's report, and commit only when Alan says so.** Its rules, each from a real failure here: it never adds, removes or reorders rows (what the tabs cover is Alan's call — the ABT/SLB/VEEV/KGS gaps are Open Items #28); it never blanks a cell the provider has no figure for (the JEPQ/SPMO market caps came from another source), but it does clear a yield the provider reports as nothing paid in 12 months (ETSY, NFLX, PLTR and MLPI carried stale 0.5-0.8% yields until 10/4); it never replaces a future earnings date with a past one; it checks each column's header before writing; and it flags a quote more than 3% from the Friday close it just appended. Audit findings under `scoring_verification` are reported on every run but do not gate it (it never touches Scoring); any other audit failure does. `landry export` no longer fills Market Data either — its only source was `landry_snapshot.json`, whatever the last `refresh` left (five days stale on 10/4).
